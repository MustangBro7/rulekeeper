A field report on instruction files

We measured what coding agents actually do with your instructions.

Everyone writes CLAUDE.md and AGENTS.md files. Nobody measures whether they work. So we joined four weeks of real agent transcripts — 59 sessions, 3,095 commands — against every rule in the instruction files they were supposed to follow. The results changed how we write them.

Finding 2 — When a rule is delivered, it works

One repo carried a hard requirement: verify UI changes in a live preview before calling the task done. The rule was added mid-window, which gave us a natural experiment. Adherence went from 78% before the rule existed to 93% after — and in the twelve sessions where the file was demonstrably in context, adherence was twelve for twelve. The single violation came from a session that never saw the file.

Rules are dated by the git commit that introduced them — sessions older than a rule are never accused. That’s what makes before/after measurement honest.

Finding 3 — Some rules were already dead on arrival

The adjacent rule in the same file — “run standard checks” — was followed nine times out of nine before it was ever written. Agents do this by default. The line is dead weight, and it isn’t alone: 8 of the 23 rules we scored were never exercised once in four weeks.

The method — in one paragraph

RuleKeeper reads the session logs your agents already write to disk, attributes each session to the repos it touched, extracts machine-checkable rules from your instruction files, and scores them: delivered? followed? violated? dead? Local-first — your code and transcripts never leave the machine.
